# بررسی UX — تب لیست مشتریان

تاریخ بررسی: ۱۴۰۴/۰۵/۲۰  
محدوده: شیت `#sheet-customers` (نه داشبورد)  
فایل‌های اصلی: `index.html`، `src/customers.js`، `src/main.js`، `src/bulk.js`، `src/pagination.js`، `src/transfers.js`، `src/import-export.js`، `src/styles.css`

هدف این سند: فهرست مشکلات و اصلاحات تجربه کاربری، اولویت‌بندی‌شده، تا یکی‌یکی فیکس شوند.

---

## نحوه کار با این لیست

- هر آیتم یک **شناسه** دارد (`C-01` و …).
- ستون **وضعیت** را هنگام فیکس به `در حال انجام` / `انجام شد` تغییر دهید.
- پیشنهاد ترتیب فیکس: اول **P0**، بعد **P1**، بعد **P2**.

| اولویت | معنی |
|--------|------|
| P0 | باگ یا گیج‌کنندگی جدی؛ کاربر را گمراه یا گیر می‌اندازد |
| P1 | اصطکاک روزانه؛ ارزش فیکس بالا |
| P2 | پولیش، دسترس‌پذیری، موبایل، یکپارچگی با بقیه تب‌ها |

---

## خلاصه اجرایی

لیست مشتریان یک جدول فیلترپذیر/مرتب‌پذیر با پنل جزئیات غنی است. بیشترین درد UX از این‌هاست:

1. برچسب‌های آمار گمراه‌کننده و ناسازگار با داشبورد
2. صفحه‌بندی که با بعضی فیلترها ریست نمی‌شود
3. سورت ناقص/غلط (شماره، آخرین پیگیری) بدون نشانگر بصری
4. انتخاب ردیف که بعد از رندر دوباره sync نمی‌شود
5. empty state یکسان برای «هیچ داده‌ای نیست» و «فیلتر نتیجه نداد»

الگوی خوب برای الگوبرداری: empty state هوشمند تب فالوآپ‌ها در `followups.js`.

## P0 — باگ و گیج‌کنندگی جدی

### C-01 — برچسب آمار «کل مشتریان» با مقدار واقعی جور نیست
- **وضعیت:** انجام شد
- **مشکل:** کارت `#stat-ld` با لیبل «کل مشتریان» و رنگ LD، در واقع تعداد کسانی را نشان می‌دهد که **فروش قابل‌شمارش** دارند (`hasPurchase`)، نه تعداد LD و نه «همه مشتریان».
- **اثر:** کاربر/مدیر عدد را با LD یا با «کل مخاطبین» اشتباه می‌گیرد؛ در داشبورد هم «کل مشتریان» معنای دیگری دارد (`datedCustomers.length`).
- **پیشنهاد فیکس:**
  - لیبل را به چیزی مثل «خریداران» / «مشتریان دارای فروش» تغییر دهید، **یا**
  - مقدار را با تعریف محصول هم‌راستا کنید و `id="stat-ld"` را هم rename کنید تا سوءتفاهم کد هم کم شود.
- **فیکس اعمال‌شده:** لیبل کارت به «خریداران» تغییر کرد.
- **فایل‌ها:** `index.html` (~812)، `customers.js` → `updateStats` (~344–347)

### C-02 — کارت «تبدیل شده (LD→CS)» برای کاربر غیر سازمانی همیشه ۰ است
- **وضعیت:** انجام شد
- **مشکل:** اگر `canViewOrgWideData()` نباشد، مقدار همیشه `0` ست می‌شود؛ کاربر ممکن است فکر کند تبدیلی اتفاق نیفتاده.
- **پیشنهاد فیکس:** کارت را برای نقش‌های بدون دسترسی مخفی کنید، یا مقدار scoped واقعی نشان دهید، یا با توضیح/tooltip شفاف کنید که این آمار سازمانی است.
- **فیکس اعمال‌شده:** برای دید سازمانی همان `convertedCount`؛ برای بقیه تعداد مشتریان CS در اسکوپ خودشان.
- **فایل‌ها:** `customers.js` → `updateStats` (~352)، `index.html` (~815)

### C-03 — فیلتر پلتفرم / وضعیت / سطح، صفحه را ریست نمی‌کند
- **وضعیت:** انجام شد
- **مشکل:** `filterSig` فقط `search|advisor|transfer` است. تغییر `#filterPlatform` / `#filterStatus` / `#filterCustomerLevel` صفحه را روی ۱ برنمی‌گرداند → کاربر روی صفحه ۳ می‌ماند و جدول خالی می‌بیند در حالی که نتیجه در صفحات قبل است.
- **پیشنهاد فیکس:** همه فیلترهای مؤثر را داخل `filterSig` بگذارید (یا از خود `filtered` hash استفاده کنید).
- **فیکس اعمال‌شده:** `platform` / `status` / `level` به `filterSig` اضافه شد.
- **فایل‌ها:** `customers.js` → `renderCustomers` (~211–212)، الگوی درست در `pagination.js`

### C-04 — سورت «آخرین پیگیری» با نمایش جدول ناسازگار است
- **وضعیت:** انجام شد
- **مشکل:** رندر با `sortFollowupsNewestFirst` آخرین مورد را می‌گیرد؛ سورت با `.pop()` روی آرایه فیلترشدهٔ بدون ترتیب قطعی — ترتیب سورت می‌تواند با ستون نمایش‌داده‌شده فرق کند.
- **پیشنهاد فیکس:** همان منطق تاریخ/مرتب‌سازی نمایش را در `sortCustomers` برای `lastFollowup` استفاده کنید.
- **فیکس اعمال‌شده:** سورت با همان کلید `doneAt||date` و ترتیب newest-first نمایش هم‌راستا شد.
- **فایل‌ها:** `main.js` → `sortCustomers` (~137–139)، `customers.js` (~242–247)

### C-05 — سورت «شماره» روی فیلد قدیمی `phone` است
- **وضعیت:** انجام شد
- **مشکل:** نمایش از `phones[]` / `formatPhonesDisplay` است؛ سورت `a.phone` / `b.phone` را مقایسه می‌کند و برای مشتریان فقط با `phones` غلط یا خالی می‌شود.
- **پیشنهاد فیکس:** با `getPrimaryPhone(c)` سورت کنید (مثل فالوآپ‌ها).
- **فیکس اعمال‌شده:** سورت ستون شماره با `getPrimaryPhone` انجام می‌شود.
- **فایل‌ها:** `main.js` → `sortCustomers` (~131–153)

### C-06 — انتخاب ردیف بعد از رندر از بین می‌رود / با select-all ناسازگار است
- **وضعیت:** انجام شد
- **مشکل:**
  1. `selectedIds` در حافظه می‌ماند ولی checkboxهای جدید unchecked ساخته می‌شوند.
  2. `updateSelectAllCheckbox` تعداد **کل انتخاب‌ها** را با تعداد checkbox **صفحه فعلی** مقایسه می‌کند → روی صفحه بعد ممکن است «انتخاب همه» تیک‌خورده دیده شود در حالی که هیچ ردیفی تیک ندارد.
- **اثر:** عملیات دسته‌جمعی روی آیتم‌هایی که کاربر روی صفحه نمی‌بیند، یا حس «انتخاب شده ولی تیک نیست».
- **پیشنهاد فیکس:**
  - بعد از `renderCustomers` وضعیت checkboxها را از `selectedIds` restore کنید.
  - منطق select-all را صفحه‌محور کنید (فقط checkboxهای صفحه فعلی).
  - اختیاری: با تغییر فیلتر/جستجو، انتخاب را clear کنید یا به کاربر بگویید.
- **فیکس اعمال‌شده:** `restoreSelection` بعد از رندر؛ `updateSelectAllCheckbox` فقط وضعیت صفحه فعلی را می‌سنجد.
- **فایل‌ها:** `bulk.js` (~31–69)، `customers.js` → رندر checkbox (~227–228)

## P1 — اصطکاک روزانه

### C-07 — Empty state یکسان و گمراه‌کننده
- **وضعیت:** انجام شد
- **مشکل:** برای هر حالت خالی همان متن «مشتری‌ای یافت نشد / مشتری جدید اضافه کنید» نشان داده می‌شود؛ حتی وقتی فیلتر/سرچ همه را حذف کرده.
- **پیشنهاد فیکس:** مثل فالوآپ‌ها تفکیک کنید:
  - بدون داده در اسکوپ → دعوت به افزودن (اگر perm دارد)
  - سرچ بدون نتیجه → «نتیجه‌ای برای …» + دکمه پاک کردن سرچ
  - فیلتر فعال بدون نتیجه → توضیح + دکمه «پاک کردن فیلترها»
- **فیکس اعمال‌شده:** empty state بر اساس سرچ / فیلتر / خالی بودن اسکوپ تفکیک شد؛ `clearCustomerSearch` و `clearCustomerFilters` اضافه شد.
- **فایل‌ها:** `customers.js` (~195–203)، الگو: `followups.js` → `buildFollowupEmptyHtml`

### C-08 — دکمه / اکشن «پاک کردن فیلترها» وجود ندارد
- **وضعیت:** انجام شد
- **مشکل:** ۵ فیلتر + سرچ؛ برگشتن به حالت پیش‌فرض دستی و کند است. در کد هم `clearCustomerFilters` نیست.
- **پیشنهاد فیکس:** دکمه «پاک کردن فیلترها» وقتی حداقل یک فیلتر/سرچ فعال است؛ یا chipهای فیلتر فعال با ×.
- **فیکس اعمال‌شده:** دکمه در تولبار فقط وقتی سرچ/فیلتر فعال است نمایش داده می‌شود.
- **فایل‌ها:** `index.html` toolbar، `customers.js`

### C-09 — فیلتر سطح مشتری هست، ستون سطح نیست
- **وضعیت:** انجام شد
- **مشکل:** `#filterCustomerLevel` هست ولی در جدول سطح دیده نمی‌شود (فقط در پنل جزئیات).
- **اثر:** کاربر نمی‌فهمد چرا ردیفی آمده/نیامده؛ مقایسه سریع سطح‌ها ممکن نیست.
- **پیشنهاد فیکس:** ستون سطح (یا badge کنار نام) با همان `formatCustomerLevel` / `customer-level-badge`.
- **فیکس اعمال‌شده:** ستون «سطح» با badge بعد از نام اضافه شد.
- **فایل‌ها:** `index.html` thead، `customers.js` row render، `utils.js` → `CUSTOMER_LEVELS`

### C-10 — ستون «توضیحات» معنای مبهم دارد
- **وضعیت:** انجام شد
- **مشکل:** اولویت با `lastNote` آخرین پیگیری است، وگرنه `c.notes`. هدر فقط «توضیحات» است؛ کاربر فکر می‌کند یادداشت ثابت مشتری است.
- **پیشنهاد فیکس:** هدر را به «آخرین یادداشت» تغییر دهید، یا دو منبع را جدا کنید؛ در `title` هم منبع را مشخص کنید.
- **فیکس اعمال‌شده:** هدر به «آخرین یادداشت»؛ `title` منبع (پیگیری یا یادداشت ثابت) را نشان می‌دهد.
- **فایل‌ها:** `index.html` (~873)، `customers.js` (~248، ~295)

### C-11 — آمار بالای صفحه به فیلتر فعال واکنش نمی‌دهد
- **وضعیت:** انجام شد
- **مشکل:** `updateStats` روی کل اسکوپ است، نه روی `getFilteredCustomers()`. با فیلتر فعال، اعداد کارت‌ها با جدول جور نیستند.
- **پیشنهاد فیکس (یکی از دو رویکرد):**
  - A) آمار همیشه اسکوپ کامل بماند ولی برچسب «در اسکوپ شما» داشته باشد؛ کنار جدول تعداد فیلترشده نشان دهید (`نمایش X از Y`).
  - B) وقتی فیلتر فعال است، آمار هم روی مجموعه فیلترشده حساب شود + نشانگر «بر اساس فیلتر».
- **فیکس اعمال‌شده:** رویکرد A — راهنمای «آمار بر اساس اسکوپ شما» + خلاصه «نمایش N از M … با فیلتر فعال».
- **فایل‌ها:** `customers.js` → `updateStats`، pagination info از قبل `from/to/total` دارد

### C-12 — ورود به تب مشتریان لیست را refresh نمی‌کند
- **وضعیت:** انجام شد
- **مشکل:** در `switchTab` برای dashboard/followups/sales/... رندر صدا زده می‌شود؛ برای `customers` نه.
- **اثر:** اگر داده از مسیر دیگری عوض شده و `renderCustomers` صدا نخورده باشد، UI کهنه می‌ماند (live-sync معمولاً کمک می‌کند ولی پوشش کامل نیست).
- **پیشنهاد فیکس:** `if (tab === 'customers') renderCustomers()` مثل بقیه تب‌ها.
- **فیکس اعمال‌شده:** `renderCustomers()` هنگام ورود به تب مشتریان صدا زده می‌شود.
- **فایل‌ها:** `main.js` → `switchTab` (~103–109)

### C-13 — نشانگر سورت روی هدرها نیست
- **وضعیت:** انجام شد
- **مشکل:** کلیک روی `<th>` سورت می‌کند ولی هیچ ▲/▼ یا `aria-sort` نیست؛ کاربر نمی‌فهمد الان روی کدام ستون و کدام جهت است.
- **پیشنهاد فیکس:** کلاس/آیکون روی هدر فعال + `aria-sort="ascending|descending"`؛ ترجیحاً `button` داخل `th` برای کیبورد.
- **فیکس اعمال‌شده:** دکمه داخل هدرهای قابل‌سورت + نشانگر ▲/▼ و `aria-sort`.
- **فایل‌ها:** `main.js` → `sortCustomers` / `sortCustomersHeader`، `index.html` thead، `styles.css`

### C-14 — بازه «۷ روز» برای فیلتر انتقال در UI گفته نشده
- **وضعیت:** انجام شد
- **مشکل:** گزینه «تازه‌منتقل‌شده / تازه‌ارسال‌شده» با `isRecentTransferredIn/Out(..., 7)` کار می‌کند ولی متن گزینه بازه را نمی‌گوید.
- **پیشنهاد فیکس:** متن گزینه را مثل «تازه‌منتقل‌شده به من (۷ روز)» کنید یا tooltip بگذارید.
- **فیکس اعمال‌شده:** متن گزینه‌ها به «(۷ روز)» به‌روز شد و `title` روی select گذاشته شد.
- **فایل‌ها:** `index.html` (~838–841)، `customers.js` (~118–122)

### C-15 — حذف دسته‌جمعی شکست جزئی را پنهان می‌کند
- **وضعیت:** انجام شد
- **مشکل:** خطای تک‌ردیفی فقط `console.error`؛ toast فقط «N مورد حذف شد» می‌گوید. اگر بعضی fail شوند کاربر نمی‌فهمد.
- **پیشنهاد فیکس:** toast مثل «۱۲ حذف شد، ۲ ناموفق» + در صورت امکان نام/شناسه ناموفق‌ها.
- **فیکس اعمال‌شده:** شمارش موفق/ناموفق + نمونه نام/شناسه در toast.
- **فایل‌ها:** `bulk.js` → `bulkDelete` (~149–213)

### C-16 — confirm حذف با `window.confirm` خام است
- **وضعیت:** انجام شد
- **مشکل:** برای bulk delete از `confirm()` مرورگر استفاده می‌شود؛ با مودال حذف تکی و بقیه UI ناسازگار است و در بعضی محیط‌ها/موبایل تجربه بدتری دارد.
- **پیشنهاد فیکس:** همان الگوی `#deleteModal` یا مودال تأیید مشترک با تعداد آیتم‌ها.
- **فیکس اعمال‌شده:** تأیید bulk delete از `#deleteModal` با تعداد و نوع آیتم‌ها انجام می‌شود.
- **فایل‌ها:** `bulk.js` (~144)، `index.html` delete modal

### C-17 — جستجو بدون debounce روی هر `input` کل جدول را rebuild می‌کند
- **وضعیت:** انجام شد
- **مشکل:** `oninput="app.renderCustomers()"` + فیلتر سطح با `resolveCustomerLevel` روی هر مشتری می‌تواند روی دیتای بزرگ سنگین باشد؛ هنگام تایپ سریع UI می‌پرد.
- **پیشنهاد فیکس:** debounce ~200–300ms برای سرچ؛ فیلترهای select همان `change` بمانند. ایندکس followup-per-customer برای رندر هم کمک می‌کند (الان per-row `filter` روی کل followups).
- **فیکس اعمال‌شده:** `onCustomerSearchInput` با debounce ۲۵۰ms؛ selectها همچنان فوری.
- **فایل‌ها:** `index.html` (~825)، `customers.js`، `main.js`

### C-18 — Select-all وقتی بعضی ردیف‌ها checkbox ندارند گیج‌کننده است
- **وضعیت:** انجام شد
- **مشکل:** ستون انتخاب برای perm نشان داده می‌شود، ولی بعضی ردیف‌ها (`!canSelect`) سلول خالی دارند. «انتخاب همه» فقط checkboxهای موجود را می‌گیرد؛ کاربر فکر می‌کند همه صفحه انتخاب شده.
- **پیشنهاد فیکس:** برای ردیف‌های غیرقابل‌انتخاب checkbox disabled با title دلیل؛ یا در شمارش/متن bulk مشخص کنید «N قابل‌انتخاب از M».
- **فیکس اعمال‌شده:** checkbox غیرفعال با توضیح؛ select-all فقط قابل‌انتخاب‌ها؛ title و متن bulk تعداد قابل‌انتخاب صفحه را نشان می‌دهد.
- **فایل‌ها:** `customers.js`، `bulk.js` → `toggleSelectAll` / `updateBulkUI`

## P2 — پولیش، موبایل، دسترس‌پذیری

### C-19 — موبایل: فقط اسکرول افقی جدول، بدون نمای کارت
- **وضعیت:** انجام شد
- **مشکل:** فالوآپ‌ها روی موبایل `followup-cards-view` دارند؛ مشتریان `min-width: 700px` + اسکرول افقی. با ~۱۰ ستون کار با موبایل سخت است.
- **پیشنهاد فیکس:** نمای کارت فشرده (نام، شماره، وضعیت، پیگیری بعدی، کارشناس) + تپ برای باز کردن جزئیات.
- **فیکس اعمال‌شده:** `#customerCards` با کارت فشرده؛ روی ≤768px جدول مخفی و کارت‌ها نمایش داده می‌شوند.
- **فایل‌ها:** `styles.css`، `customers.js`، `index.html`

### C-20 — Toolbar فیلترها شلوغ است
- **وضعیت:** باز
- **مشکل:** سرچ + ۵ select + دکمه انتقال + منوی خروجی + CTA در یک نوار؛ روی دسکتاپ wrap می‌شود، روی موبایل گرید ۲ستونه ولی اولویت بصری ضعیف است.
- **پیشنهاد فیکس:** گروه‌بندی (جستجو جدا، فیلترها در ردیف/drawer)، یا «فیلترهای بیشتر» برای سطح/انتقال؛ ثابت نگه داشتن CTA «+ مشتری جدید».
- **فایل‌ها:** `index.html` (~819–857)، `styles.css` toolbar

### C-21 — دسترس‌پذیری هدرهای سورت و checkboxها
- **وضعیت:** انجام شد
- **مشکل:** `<th onclick>` با کیبورد قابل فعال‌سازی نیست؛ checkboxهای ردیف `aria-label` ندارند؛ select-all هم بدون برچسب معنادار است.
- **پیشنهاد فیکس:** دکمه داخل th، `aria-label="انتخاب مشتری X"`، label برای select-all.
- **فیکس اعمال‌شده:** دکمه‌های سورت با `aria-label`؛ select-all و checkbox ردیف برچسب دسترس‌پذیر دارند (ردیف از قبل در C-18).
- **فایل‌ها:** `index.html`، `customers.js` row HTML

### C-22 — کارت‌های آمار کلیک‌پذیر / فیلتر سریع نیستند
- **وضعیت:** باز
- **مشکل:** کارت‌هایی مثل «در حال پیگیری» یا CS فقط نمایشی‌اند؛ کاربر باید دستی فیلتر بسازد.
- **پیشنهاد فیکس (اختیاری):** کلیک روی کارت → اعمال فیلتر متناظر (مثلاً CS → فقط idهای CS اگر فیلتر نوع اضافه شود؛ following → فیلتر دارای پیگیری). فقط اگر تعریف فیلتر روشن باشد اضافه شود.
- **فایل‌ها:** `index.html` stats، `customers.js`

### C-23 — شناسه مشتری (LD/CS) در جدول دیده نمی‌شود
- **وضعیت:** باز
- **مشکل:** جستجو روی `c.id` کار می‌کند ولی ستون ایدی پلتفرم با LD/CS فرق دارد؛ پیدا کردن سریع «همان CS-…» سخت است.
- **پیشنهاد فیکس:** badge کوچک LD/CS کنار نام یا ستون باریک شناسه؛ یا کپی با کلیک.
- **فایل‌ها:** `customers.js` row، استایل `.id-ld` / `.id-cs` از قبل در CSS هست

### C-24 — Placeholder سرچ ناقص است
- **وضعیت:** انجام شد
- **مشکل:** سرچ روی شماره، ایدی، پلتفرم‌آیدی هم کار می‌کند ولی placeholder فقط «مشتری، واریزکننده، کارشناس» می‌گوید.
- **پیشنهاد فیکس:** متن را با قابلیت واقعی هم‌راستا کنید: «نام، شماره، ایدی، کارشناس، محصول…»
- **فیکس اعمال‌شده:** placeholder با فیلدهای واقعی سرچ هم‌راستا شد.
- **فایل‌ها:** `index.html` (~825)

### C-25 — عملکرد رندر: followupها به‌ازای هر ردیف دوباره filter می‌شوند
- **وضعیت:** انجام شد
- **مشکل:** برای هر مشتری دو بار `data.followups.filter(...)` + sort؛ روی لیست بزرگ کندی و پرش هنگام تایپ.
- **پیشنهاد فیکس:** یک‌بار `Map<customerId, followups[]>` بسازید و در رندر/سورت reuse کنید.
- **فیکس اعمال‌شده:** `buildFollowupsByCustomerMap` یک‌بار ساخته و در رندر، آمار و سورت استفاده می‌شود.
- **فایل‌ها:** `customers.js`، `main.js` sort

### C-26 — عدم تفکیک loading / error در لیست
- **وضعیت:** باز
- **مشکل:** لیست sync از cache است؛ حالت loading یا خطای بارگذاری مثل فالوآپ‌ها ندارد. اگر sync دیر برسد یا fail شود، کاربر فقط empty یا داده کهنه می‌بیند.
- **پیشنهاد فیکس:** اگر لایه داده وضعیت loading/error دارد، همان را در شیت مشتریان نشان دهید؛ در غیر این صورت حداقل اسکلتون/اسپینر هنگام refresh صریح.
- **فایل‌ها:** `customers.js`، در صورت نیاز `live-sync.js` / `data.js`

### C-27 — خروجی/ایمپورت داخل منوی فرعی پنهان است (قابل قبول، ولی کشف‌پذیری کم)
- **وضعیت:** باز
- **مشکل:** CSV/Excel/Import زیر «خروجی / ایمپورت ▾» است؛ برای نقش‌های import/export ممکن است دیر کشف شود.
- **پیشنهاد فیکس:** اگر استفاده زیاد است، آیکون جدا با tooltip؛ وگرنه همین ساختار با برچسب واضح‌تر کافی است. اولویت پایین.
- **فایل‌ها:** `index.html` (~847–853)

### C-28 — ناسازگاری نام‌گذاری با داشبورد
- **وضعیت:** باز
- **مشکل:** هر دو جا «کل مشتریان» برای متریک‌های متفاوت.
- **پیشنهاد فیکس:** واژه‌نامه واحد در محصول (مخاطب / سرنخ LD / مشتری دارای خرید / CS) و اعمال در داشبورد + لیست.
- **وابسته به:** C-01
- **فایل‌ها:** `index.html` (~600، ~811–812)، `dashboard.js`، `customers.js`
